Security comparison (synthesis):
- Tailscale/Headscale: WireGuard end-to-end between devices; trust in the coordination server for key distribution (Tailscale offers "Tailnet Lock" to remove that trust [U]). Good ACLs.
- Iroh: endpoints are Ed25519 public keys; QUIC + TLS 1.3 end to end; relays only forward encrypted packets [V docs "This is QUIC… TLS 1.3 handshake"]. Pairing = exchanging a ticket/public key (QR code). No third-party account.
- Cloudflare Tunnel: no inbound ports, but a public URL and TLS termination at Cloudflare.

## 2. MCP (Model Context Protocol)

- **Current spec: `2026-07-28`** (tag commit 2026-07-28) [V `git ls-remote` + tag fetch, github.com/modelcontextprotocol/modelcontextprotocol]; previous `2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`. README: schema defined in `schema/2026-07-28/schema.ts` [V].
- **Big changes in 2026-07-28** [V `docs/specification/2026-07-28/changelog.mdx`]: protocol is **stateless** (no `initialize` handshake, no `Mcp-Session-Id`; version + capabilities in every request's `_meta`); new mandatory `server/discover`; `subscriptions/listen` replaces the HTTP GET stream; **Multi Round-Trip Requests** (`input_required` results) replace server-initiated sampling/elicitation/roots requests; SSE resumability removed; tasks moved to an extension; **Roots, Sampling and Logging deprecated**; `tools/list` results get `ttlMs`/`cacheScope`.
- **Transports** [V `basic/transports/`]: `stdio` and **Streamable HTTP**. Streamable HTTP servers **MUST validate `Origin`** (DNS rebinding) and **SHOULD bind to 127.0.0.1** when local [V streamable-http.mdx lines 58–64].
- **Authorization** [V `basic/authorization/index.mdx`]: MCP server = OAuth 2.1 resource server (draft-ietf-oauth-v2-1-13); PKCE; clients MUST use Resource Indicators (RFC 8707); servers MUST validate token audience; 2026-07-28 adds RFC 9207 `iss` validation (mix-up defence), issuer-bound client credentials, `application_type` in DCR. Separate `security-considerations.mdx` (token theft, confused deputy, localhost redirect risks, CIMD trust policies).
- **Tools security** [V `server/tools.mdx`]: "there SHOULD always be a human in the loop with the ability to deny tool invocations"; clients should show confirmation prompts; "clients **MUST** consider tool annotations to be untrusted unless they come from trusted servers".
- **Security best practices doc** [V `docs/docs/2026-07-28/tutorials/security/security_best_practices.mdx`]: confused deputy, token passthrough (forbidden), SSRF, state-handle hijacking, **local MCP server compromise**, stdio-in-proxy risks, scope minimisation. The spec docs themselves do **not** use the phrase "tool poisoning" (grep found it nowhere); that term comes from security vendors (Invariant Labs, Apr 2025) [U].
- **TypeScript SDK** [V npm]: v2 split packages **`@modelcontextprotocol/server` / `@modelcontextprotocol/client` 2.2.0 (2026-09-28)**; 2.0.0 published 2026-07-27, "v2 is the stable release line, released alongside the 2026-07-28 spec"; v1 (`@modelcontextprotocol/sdk` 1.31.0, 2026-09-28, MIT) gets fixes "for at least 6 months after v2's release" [V typescript-sdk README]. Uses Standard Schema (Zod v4, Valibot…); middleware for Express/Fastify/Hono/Node with Host header validation.
- **Clients**: Claude Code 2.1.287 (2026-10-01) [V npm] uses the v2 MCP client and **2026-07-28 negotiation** with HTTP servers by default, supports remote MCP OAuth, URL-mode elicitation, stateless remote servers, and bundled `.mcpb` servers [V anthropics/claude-code CHANGELOG]. Claude Desktop (macOS/Windows) installs local servers as **MCP Bundles (`.mcpb`, formerly `.dxt`)**: zip + `manifest.json`, one-click install [V anthropics/mcpb README; `@anthropic-ai/mcpb` 2.1.2, 2025-12-04]. Remote connectors in Claude apps [U, docs blocked].
- **Advisories** [V sparse clone of github/advisory-database, github-reviewed 2025+2026, matched on "MCP"/"Model Context Protocol" in summary/details]: **404 advisories** (53 in 2025, 351 in 2026 to date); 60 critical, 140 high. Representative:
  - GHSA-7f8r-222p-6f5g / CVE-2025-49596 (2025-06-13, critical): MCP Inspector proxy had no auth (RCE from a web page).
  - GHSA-6xpm-ggf7-wc3p / CVE-2025-6514 (2025-07-09, critical): `mcp-remote` OS command injection from an untrusted server.
  - GHSA-w48q-cv73-mx4w / CVE-2025-66414 (2025-12-02, high): TS SDK did not enable DNS-rebinding protection by default. Same class in Go SDK (CVE-2026-34742, 2026-04-01) and Java SDK (CVE-2026-35568) and Google MCP Toolbox (CVE-2026-9739).
  - GHSA-345p-7cg4-v4c7 / CVE-2026-25536 (2026-02-04, high): TS SDK cross-client data leak via shared server/transport reuse.
  - CVE-2025-61260 (2026-04-14, critical): Codex CLI code execution via malicious MCP config file.
  - Dominant pattern: command injection / path traversal in third-party MCP servers, unauthenticated HTTP MCP endpoints (nginx-ui CVE-2026-33032, meta-ads-mcp CVE-2026-48039).
  Full list: `scratchpad/research/mcp_advisories.txt`.

**Implications for Sprint OS's own MCP server**: ship it stdio-first (spawned by Claude Desktop/Code, inherits the user's trust), and if Streamable HTTP, bind 127.0.0.1, validate Origin/Host, require a token even on localhost, and use SDK v2. Read tools default-on; write/delete tools behind per-tool permission + confirmation in our UI; treat all object content returned to the model as untrusted (prompt injection via a saved web page or file is the realistic attack).

## 3. Backups

- **restic** 0.19.1 (2026-07-05; 0.19.0 2026-06-09) [V CHANGELOG], BSD-2 [U]. Encryption: AES-256-CTR + Poly1305-AES MAC, key from password via **scrypt** [V `doc/design.rst`]. Backends: local, SFTP, **REST server**, S3, S3-compatible, B2, Azure, GCS, Swift, **rclone** [V `doc/030_preparing_a_new_repo.rst`]. `restic check --read-data` / `--read-data-subset=n/t` to verify packs [V `doc/045_working_with_repos.rst`]. rest-server 0.14.0 (2025-05-31) has **`--append-only`** (ransomware-resistant) [V]. 0.19 adds macOS "exclude cloud-backed files", zstd levels, lower-energy progress [V]. rclone 1.75.1 (2026-09-04) [V].
- **Kopia** v0.23.1 (2026-06-15), Apache-2.0 [V]; CLI + GUI, E2E encryption, compression, dedup, error correction [V README]. Friendlier GUI than restic; restic has the longer track record [opinion].
- **Litestream** v0.5.17 (2026-08-31); **v0.5.0 shipped 2025-09-30** [V tags], Apache-2.0 [V]. SQLite-only, continuous WAL shipping to S3/GCS/Azure/SFTP/file/WebDAV/NATS in the LTX format, plus a VFS for read replicas [V repo files `vfs.go`, `llms.txt`]. Creates a `_litestream_lock` table in the source DB [V README]. No client-side encryption found in source (grep) [V absence; check docs]. 0.5.x moved fast (17 patch releases in 11 months).
- **SQLite**: current 3.53.4 (2026-07-24; trunk VERSION 3.54.0) [V]. `VACUUM INTO 'file'` makes a compacted consistent copy of a live DB (implemented in `src/vacuum.c`) [V source]; available since 3.27 [U]. Online Backup API (`sqlite3_backup_*`) copies page by page while live [U, sqlite.org blocked]. **`sqlite3_rsync`** (tool/sqlite3_rsync.c, dated 2024-09-10): copies a live DB to/from `USER@HOST:PATH` bandwidth-efficiently [V source header]; needs SSH, WAL mode [U].
- **Targets**: Cloudflare **R2 free tier: 10 GB-month storage, 1M Class A, 10M Class B ops/month, free egress**, Standard class only [V cloudflare-docs `r2/pricing.mdx`]. **Backblaze B2: first 10 GB free**, ~$6/TB-month, free egress up to 3x stored [U, site blocked]. iCloud Drive folder: free 5 GB tier [U]; files are E2EE only with Advanced Data Protection [U]; syncing a live SQLite file through iCloud risks corruption, so only put **finished snapshots** (VACUUM INTO / restic repo) there [reasoned].
- **Restore testing practice** (synthesis): scheduled `restic check --read-data-subset=1/N` rotating; a monthly automatic "restore drill" that restores the latest snapshot to a temp dir, opens the SQLite file, runs `PRAGMA integrity_check` and compares row counts / a manifest hash with the live DB, and surfaces the result in the app ("Last verified restore: 3 days ago").

## 4. Always-on agents over chat apps

- **OpenClaw** (ex "Clawdbot"/"Moltbot"): v2026.9.7 (tag 2026-09-29; npm 2026-09-30) [V], **MIT** [V README], stewarded by "OpenClaw Foundation, an independent 501(c)(3)"; Gateway on your machine, channels Telegram/WhatsApp/iMessage/Slack/Discord/Signal + 20 more; native apps; models as plugins [V README]. Security: "Treat inbound messages as untrusted input… DM-capable channels pair unknown senders by default"; tools run on the host unless sandboxing is configured [V README]. **763 GitHub-reviewed advisories for the `openclaw` package (26 critical, 268 high)** in 2025–2026, e.g. pairing tokens minting admin → RCE (2026-03-13), approval bypass RCE (2026-03-02) [V advisory-database]. Star count not retrievable (API blocked) [U].
- **Letta** (ex MemGPT): `letta-ai/letta` V1 server retired to an `archive` branch; active code in `letta-ai/letta-code` (`@letta-ai/letta-code` 0.34.2, 2026-10-02, Apache-2.0) with Telegram/Slack/Discord channels [V README, npm].
- **n8n**: 2.41.6 stable (2026-10-02) [V npm]. Licence: **Sustainable Use License 1.0** + `.ee.` files under an enterprise licence [V LICENSE.md]: "You may use or modify the software only for your own internal business purposes or for non-commercial or personal use. You may distribute the software or provide it to others only if you do so free of charge for non-commercial purposes." ⇒ **cannot be bundled in or embedded into a paid product** without a commercial licence from n8n (they sell "n8n Embed" [U]). 171 advisories, 24 critical (RCE classes) [V].
- **Telegram Bot API privacy** [U, core.telegram.org blocked]: bots only use "cloud chats" (client–server encryption, messages stored on Telegram servers); secret (E2EE) chats are not available to bots. So anything said to a Telegram bot is readable by Telegram. Bot privacy mode controls only which group messages a bot sees.
- Takeaway: the pattern works and is popular, but it is the highest-risk surface in this whole design (inbound untrusted text → tools on the host). If we do it: our own small bot adapter on the hub, allowlist by chat ID, read-mostly tools, write actions require confirmation in the app, no shell tool.

## 5. Reproducible ops for a tiny hub

- **Single static binary + systemd (Linux) / launchd (macOS)**: least moving parts; health via `/healthz` + systemd `Restart=on-failure`/`WatchdogSec`; updates via signed self-update. Best fit for "same binary on Mac mini, NUC, VPS". Go (tsnet) or Rust (iroh) produce static binaries naturally; a Node server would need bundling (Node SEA / Bun compile) [U on current SEA maturity].
- **Docker Compose**: familiar for homelab users and NAS boxes (Synology/Unraid); `HEALTHCHECK`; Tailscale sidecar via `TS_AUTHKEY` + `TS_SERVE_CONFIG` [V containerboot]. Docker Desktop on Mac is heavy and has licence terms for larger companies [U].
- **Nix**: fully reproducible, Headscale ships a NixOS module [V README], but unsuitable for non-technical buyers.
- Recommendation: build one binary; publish it as (a) Mac app-embedded helper, (b) a `.deb`/tarball with a systemd unit, (c) a Docker image wrapping the same binary. Nix flake optional, community-maintained.

## 6. Jobs on a Mac when the app is closed

- **SMAppService** (macOS 13+): "register and control LoginItems, LaunchAgents, and LaunchDaemons as helper executables for your app"; `SMAppService.agent(plistName:)` points at a plist inside the bundle (`Contents/Library/LaunchAgents`); `.mainApp` registers the app itself as a login item [V developer.apple.com docs JSON]. User sees and can toggle it in System Settings → Login Items [U]. Status enum lets the app detect "requires approval" [V].
- **NSBackgroundActivityScheduler** (macOS 10.10+): system decides when to run deferrable work "based on energy usage, thermal conditions, and CPU use" [V]. Only while our process is alive. `BGTaskScheduler` is iOS/Catalyst, not AppKit macOS [V platforms list].
- **Electron**: `app.setLoginItemSettings({ type: 'mainAppService' | 'agentService' | 'daemonService' | 'loginItemService' })` maps to SMAppService [V electron `docs/api/app.md`]; `powerSaveBlocker.start('prevent-app-suspension')` [V]. Electron v44.5.1 (2026-09-29) [V].
- **Tauri**: `tauri-plugin-autostart` 2.7.0 (npm 2026-10-01) supports macOS via **LaunchAgent plist in `~/Library/LaunchAgents`** (default) or AppleScript login item, **not SMAppService** [V plugin `src/lib.rs`]; SMAppService would need a small Swift/objc2 shim. Tauri v2.12.1 (2026-09-30) [V].
- **Power / App Nap**: an agent with no UI is subject to App Nap and sleep; for a nightly job use launchd `StartCalendarInterval` (runs on wake if missed) and `ProcessInfo.beginActivity` / IOPMAssertion during the job; a sleeping laptop is not a server, which is exactly why the optional hub exists [synthesis; launchd behaviour U].

## Recommendations (for the ADR)

1. **Connectivity: embed Iroh as the default transport** (1.x since 2026-06-15, MIT/Apache, Swift+Kotlin+Node bindings): pair phone↔Mac↔hub by QR code, no account, no VPN app. Ship our own `iroh-relay` on the hub (or a $0–5 VPS) and fall back to n0's public relays, which are rate-limited and not guaranteed. **Offer Tailscale as the "power user" path** (hub joins via tsnet or `tailscale serve`); Headscale for the paranoid. Cloudflare Tunnel only for a deliberately public web endpoint, never as the default.
2. **MCP: target spec 2026-07-28 with SDK v2**; stdio first (ship as `.mcpb` for Claude Desktop), Streamable HTTP on the hub only behind the private network, Origin/Host validation and a token. Per-tool permissions, confirm-before-write, content-as-untrusted. Expect ~1 advisory a day in the ecosystem: pin and audit.
3. **Backups: SQLite `VACUUM INTO` snapshot → restic** (encrypted, verified with `check --read-data-subset`, automatic monthly restore drill shown in the UI) to the user's choice of R2 (10 GB free, verified), B2 (10 GB free, unverified), the hub's rest-server `--append-only`, or an iCloud Drive folder (snapshots only). Consider Litestream later for near-continuous hub replication, but it is SQLite-only, unencrypted and fast-moving.
4. **Always-on agent: build our own narrow Telegram adapter, don't embed OpenClaw or n8n.** n8n's licence forbids bundling in a paid product; OpenClaw is MIT but carries a large advisory history and a broad host-tool surface. Telegram is not E2EE; tell users.
5. **Hub ops: one static binary**, packaged as Mac helper + systemd unit + Docker image, `/healthz`, signed self-update.
6. **Mac background: SMAppService launch agent** (macOS 13+) running the same binary as the hub, so "Mac only" and "Mac + hub" share code. If Tauri, add a small SMAppService shim; Electron has it built in.
